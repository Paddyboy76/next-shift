Act as an adversarial Fortified Enterprise Fleet judge and release engineer.

- messy input decomposition;
- multiple simultaneous operational issues;
- deterministic owner routing;
- least-privilege denial;
- asynchronous execution;
- idempotency;
- retry/DLQ behavior;
- durable cross-shift state;
- trusted evidence;
- evidence failure;
- independent verification;
- operational history;
- memory provenance and advisory-only behavior;
- registry/lifecycle visibility;
- observability lifecycle;
- Gateway/Model Armor proof;
- controlled recovery/replanning;
- current deployed UI;
- reproducibility.

Inspect authoritative state rather than trusting agent prose.

Run meaningful tests and production readiness.

Remove debugging debris and stale claims.

Do not introduce a new feature during final acceptance unless required to fix an actual failing acceptance criterion.

Finish only when the branch is suitable for merge to `main`.
