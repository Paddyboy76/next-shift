# Mission 15 — Four-Minute Demo + Public Polish

Optimize the actual deployed product for a judge seeing it for the first time.

The demo should rapidly communicate:

- messy handover becomes durable operational work;
- several cross-department issues emerge;
- agents have constrained authority;
- work persists across shifts;
- real execution happens;
- completion requires trusted evidence;
- an independent verifier owns closure;
- failures are visible and recoverable;
- memory improves operations over time rather than merely remembering facts;
- security and observability are real.

Use only features that really work.

Do not add maps, video generation, music generation, decorative model calls, or other gimmicks unless a concrete operational requirement unexpectedly makes them valuable.

Do not include clinical, medication, or dietary workflows in the public demo.

Make the synthetic hospital setting obvious while preserving general 24/7-enterprise applicability.
